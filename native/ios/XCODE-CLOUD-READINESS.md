# Xcode Cloud readiness

Audit date: 7 November 2026. No Apple account was connected, no Cloud workflow was created or started, and no signing settings were changed.

## Project and clean-checkout result

- The native project is `Fylogia.xcodeproj`. The shared `Fylogia` scheme builds the `Fylogia` app and its `FylogiaWidgetExtension` dependency, and includes `FylogiaTests` and `FylogiaUITests` in its Test action. The widget scheme shown by `xcodebuild -list` is generated, not a shared scheme; use the shared app scheme so the extension is embedded in the app.
- App bundle ID: `com.fylogia.native`. Widget bundle ID: `com.fylogia.native.widget`. Both targets use Automatic signing, target iPhone and/or iPad, and have an iOS 17.0 deployment target. `DEVELOPMENT_TEAM` is not set. No entitlements, Swift packages, `Package.resolved`, CocoaPods, or Carthage dependencies are present.
- Local Xcode is 27.2 (27B52). `xcodebuild -list` and `-describeAllArchivableProducts` recognize the app and widget products. The shared app scheme has Build, Test, Analyze, Profile, and Archive actions.
- A clean Git clone initially compiled but produced an app without `WebAssets/index.html`. `native/ios/Fylogia/WebAssets/` is generated and ignored, so compile success alone did not prove a runnable app. The new root `ci_scripts/ci_post_clone.sh` archives the immutable `fylogia-web-golden-v1` source tag, installs its locked npm dependencies with Node 24, and builds native-only WebAssets before Xcode runs. It does not edit the Web checkout or production.
- **PASS clean-checkout validation:** On a fresh clone, the post-clone script completed `npm ci` and transformed the golden source; Xcode then built the Debug simulator app with `WebAssets/index.html` embedded. `xcodebuild build-for-testing` also succeeded for the app, widget, unit tests, and UI test runner. DerivedData and logs were written under `/Volumes/Developments/Xcode/`.

## Focused manual Cloud test plan (7 November 2026)

- Added the shared, non-default `Fylogia-Focused-Cloud` test plan. It runs the complete `FylogiaTests` unit-test target and only these stable UI navigation cases: `HybridUITests.testLandscapeFeedUsesHorizontalScrollingWithoutCurl`, `HybridUITests.testArticleModesAndNavigationSurviveRotation`, and `HybridUITests.testGoldenNavigationSettingsAndScreenshots`. These cover facing-page horizontal scroll without either curl engine, article return/rotation, and essential navigation/Settings discovery. The plan deliberately excludes experimental curl tests.
- The plan is available through the shared `Fylogia` scheme, but is not its default test plan. Existing default scheme test selection remains unchanged.
- Intended workflow: configure in Xcode Cloud as **manual start only**, selecting `native-ios-foundation` and the `Fylogia` scheme with `Fylogia-Focused-Cloud`. Do not attach it to Web `main`, scheduled news refreshes, routine website data commits, or automatic pull-request/push triggers. The repository does not start or configure the account-side workflow.
- **Local validation:** `xcodebuild -showTestPlans` recognizes the shared plan; the plan-target build succeeds with `build-for-testing`, one build job, and code signing disabled. This compiles test products only; it does not boot a simulator or execute XCTest.
- **Owner gate:** Do not configure signing, connect an account, or start a Cloud build until Apple Developer enrollment/team status is confirmed. The authenticated account's Cloud access, supported Xcode versions and destinations still require owner verification.

## Cloud version and signing gates

- The installed local Xcode 27.2 build is verified. Apple publishes a version-specific Xcode Cloud version/test-destination list through the App Store Connect API; that authenticated list and the account’s Cloud environment selector were not accessed. Confirm Xcode 27.2 and the desired simulator destinations in the owner’s Xcode Cloud workflow environment before selecting them. The current Xcode Cloud API exposes both supported Xcode versions and simulator test destinations: [Apple API reference](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-cixcodeversions). The public Xcode Cloud release notes do not establish availability for this specific account/version: [Apple Xcode Cloud release notes](https://developer.apple.com/xcode-cloud/release-notes/).
- Xcode 27’s September 2026 update announces Cloud build/test setup without Developer Program membership. Apple’s general Cloud setup documentation still describes Developer Program/App Store Connect app-record prerequisites. Treat account onboarding as an owner check in Xcode’s Cloud pane, and do not add a paid plan for development testing: [Xcode updates](https://developer.apple.com/documentation/Updates/xcode), [Cloud setup requirements](https://developer.apple.com/documentation/xcode/Setting-up-your-project-to-use-Xcode-Cloud).
- Apple lists 25 Xcode Cloud compute hours/month included with Developer Program membership and offers paid tiers beyond that. The allowance for Xcode 27’s no-membership build/test path was not confirmed, so check the account’s usage panel before enabling automatic runs: [Xcode Cloud plans](https://developer.apple.com/xcode-cloud/get-started/).
- The source identifies the required bundle IDs but no exact Apple team ID or App Store Connect app record. An owner must select the intended Fylogia team; do not use another project’s team or signing identity. For TestFlight/App Store distribution, create or confirm the App Store Connect app record for `com.fylogia.native`, enable Automatic signing for the app and widget under that same team, and ensure the corresponding identifiers/capabilities are provisioned. Distribution requires the owner-approved Developer Program/App Store Connect access. No distribution workflow is proposed here.

## Suggested economical workflows

1. **Focused development check:** Manually start, or trigger only from pushes/PRs on `native-ios-foundation`. Use the shared `Fylogia` scheme, one Cloud-supported iPhone simulator destination, a test plan containing the unit tests plus one fast UI smoke test, and no Archive or distribution action. Keep parallel destinations off. No `.xctestplan` is currently committed, so create and validate this focused plan before enabling the workflow. Run local WebKit regressions before this action; avoid downloading a separate Playwright browser into each Cloud run until Cloud quota and runtime support are confirmed.
2. **Manual acceptance:** Start manually after a candidate is stable. Use the broader unit/UI test plan and one Cloud-supported iPhone plus one iPad simulator destination, with no TestFlight post-action. Run the remaining WebKit, VoiceOver, sustained-performance, and physical Duo checks on their appropriate local/hardware workflows. Add more destinations only when they close a defined acceptance gap.

Apple’s Xcode Cloud workflows are configured in Xcode/App Store Connect; they are not defined by this repository’s GitHub workflow file. Restrict Cloud start conditions to `native-ios-foundation` and manual runs. Do not attach a workflow to every `main` push: the existing scheduled Web refresh commits `public/data/edition.json` to `main`, and native Cloud validation must not run for those data-only refreshes. The current GitHub Pages workflow itself is separate: quality/browser jobs trigger on PRs and pushes to `main`, while the four-hour schedule only refreshes news.
